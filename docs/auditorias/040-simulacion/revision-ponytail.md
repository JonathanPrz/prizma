# ponytail-review · Phase A

What this change does: This change adds an offline audit of the current selection engine. It runs the nine supplied seeds, 720 synthetic variants, 1,235 matched comparisons and nine text contrasts, then reports coverage, ties, input sensitivity, information gain and output groups. It does not change the app or start phases B and C.

Looks good. Ship.

Reviewed simular.cjs, verificar.cjs, the report and generated records against the current app.js callers and helpers: normalizarDatos, both person normalizers, visibles, primerasDua, compararPertinenciaDua, accesosVisibles, practicasVisibles, compararAcceso, objetivosVisibles, fichasPracticaProfesional, ajustesTrabajo and the three renderers. Also read the seed JSON, advisory text, proposed flow, AGENTS.md and task. Assumed one local audit run, not a public service or production prediction system.

The adapter preserves static HTML container links so objectives, DEC and placement blocks are counted. It checks their sets against the real eligibility functions and checks the first groups against the real ranking. It distinguishes a course without a personal case from an existing case whose last frequency is removed. That boundary has an assertion; generic blocks do not vanish because of an adapter shortcut.

The generator is bounded, deterministic and excludes duplicate inputs and the original seeds. Variants carry an explicit warning that inherited expectations are not a newly validated oracle. Counts by ID and by DUA consideration are separate. The report does not label every non-expected card as wrong, confuse a missing first group with an empty list, or treat text fields with no ranking effect as useless.

The information calculation is checked against independent and perfectly dependent toy inputs. Matched comparisons hold other inputs and case presence fixed. The report explicitly identifies a spurious association between placement and DUA instead of calling it a direct effect. Output grouping uses a fixed representative, a stated Jaccard threshold and domain separation; every membership is checked. No clinical or predictive validation is claimed.

Both scripts use standard Node modules and write only here. No network module is loaded; fetch and require are absent from the app vm, and startup is omitted. The application and source inputs retain their hashes. The verifier repeated all eleven generated result files byte for byte, recounted metrics and checked scope. The catalog validator passed. No package, app migration or speculative UI was added.

Not checked: Browser rendering, focus, assistive technology, downloads or print; external real cases; the clinical validity of the AI-authored seed expectations or of the 720 inherited variant references. Browser reauditing belongs to phase C after B is integrated. Human review of the five prose/JSON differences remains necessary for interpreting later comparisons.
